Valence is configured almost entirely through environment variables, plus a handful of settings held in the database and edited on the admin settings page. This page lists every variable defined in the code and in the compose files. For a walkthrough of the ones you are likely to change, read [Configuration](/install/configuration) first.

## How to read this page

Valence runs as up to four services, and each one reads its own variables.

| Service       | What it is                                                                                 | Where it is configured                                    |
| :------------ | :----------------------------------------------------------------------------------------- | :-------------------------------------------------------- |
| Server        | The API, the web client and the jobs, `apps/server`                                        | The `valence` service in `compose.yaml`                   |
| Media service | The Rust transcoder, `valence-transcoder`, started beside the server in the same container | The same `valence` service, since it shares the container |
| Requests      | The optional service that finds and downloads titles, `apps/requests`                      | The `requests` service                                    |
| Compose       | Variables that only `compose.yaml` reads, to fill in the settings above                    | Your `.env` file or your stack editor                     |

Three points apply to everything below.

- **Types are checked at start.** The server and the requests service validate their variables when they start, and a bad value stops them with a message naming the variable. A boolean must be exactly `true` or `false`, and numbers must be whole numbers greater than zero unless stated.
- **Compose forwards only some of them.** The `compose.yaml` in the repository passes a chosen set of variables to the `valence` container. To set one that is not listed in its `environment` block, add it there. The tables say which variables compose forwards.
- **Some things are not variables at all.** First-run setup stores the trusted origins and the secure cookie flag in the database, and the admin settings page changes them afterwards. The variables only supply their values until then, as described under Authentication.

Defaults in the "Default" column are what the code uses when nothing is set. Where the Docker image or `compose.yaml` sets a different value, the description says so.

### Authentication

| Variable                         | Type                           | Default                                      | Description                                                                                                                                                                                                                  |
| :------------------------------- | :----------------------------- | :------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `BETTER_AUTH_SECRET`             | string, at least 32 characters | `development-secret-change-me-in-production` | The secret that seals sign-in cookies. Changing it signs everybody out. Always set your own, for example with `openssl rand -base64 48`. Compose requires it.                                                                |
| `BETTER_AUTH_URL`                | URL                            | `http://localhost:8420`                      | The address a browser reaches Valence at, which is the proxy's and not the container's. Sign-in builds its redirects from it, and passkeys derive their relying party from its hostname. Compose takes it from `PUBLIC_URL`. |
| `TRUSTED_ORIGINS`                | comma separated list of URLs   | `http://localhost:5173`                      | Every address the web client is served from. A browser signing in from an unlisted origin is refused. Values are trimmed and empty entries dropped. Compose takes it from `PUBLIC_URL`.                                      |
| `COOKIE_SECURE`                  | `true` or `false`              | `false`                                      | Whether session cookies carry the `Secure` attribute. Set it to `true` only when the instance is reached over HTTPS, since a secure cookie is never sent over plain HTTP. Compose defaults it to `true`.                     |
| `AUTH_RATE_LIMIT_ENABLED`        | `true` or `false`              | `true`                                       | Turns the authentication rate limiter on or off.                                                                                                                                                                             |
| `AUTH_RATE_LIMIT_WINDOW_SECONDS` | integer                        | `60`                                         | The length of the rate limit window, in seconds.                                                                                                                                                                             |
| `AUTH_RATE_LIMIT_MAX`            | integer                        | `60`                                         | The number of requests allowed per window, per caller and path.                                                                                                                                                              |

`TRUSTED_ORIGINS` is not the only source of trusted origins. The server trusts the union of this variable, the origins stored in its settings (chosen during first-run setup and editable on the admin settings page), the addresses its own network interfaces hold, and the desktop client's own `valence://` scheme. Changing the variable later adds origins rather than replacing the stored ones. The secure cookie flag chosen at first-run setup is stored in the database too, and once setup has run, the stored value is the one the server uses (a change to it takes effect when the server restarts). So `COOKIE_SECURE` is the starting value for a fresh install, and editing the variable later does not override what setup recorded.

### Database and upgrades

| Variable                | Type              | Default           | Description                                                                                                                                                  |
| :---------------------- | :---------------- | :---------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `MIGRATE_ON_START`      | `true` or `false` | `true`            | Whether the server brings the database schema up to date when it starts. Set it to `false` to run `Migrate.js` by hand. See [CLI reference](/reference/cli). |
| `BACKUP_BEFORE_MIGRATE` | `true` or `false` | `true`            | Whether a snapshot of the database is taken with `pg_dump` before a migration changes an existing database.                                                  |
| `BACKUP_DIR`            | path              | `/config/backups` | Where those snapshots are written. It is inside the `config` volume, so it is kept.                                                                          |
| `BACKUPS_KEPT`          | integer           | `3`               | How many snapshots to keep. Older ones are pruned. Compose forwards it, default `3`.                                                                         |

Compose forwards only `BACKUPS_KEPT` from this group. To use `MIGRATE_ON_START`, `BACKUP_BEFORE_MIGRATE` or `BACKUP_DIR`, add them to the `environment` block of the `valence` service.

### Media service and requests

| Variable          | Type                           | Default                             | Description                                                                                                                                                                                 |
| :---------------- | :----------------------------- | :---------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `TRANSCODER_URL`  | `unix:` path or `http://` URL  | `unix:/run/valence-transcoder.sock` | Where the server dials the media service. The media service also reads this to decide where to listen, so one setting serves both ends. The image sets `unix:/run/valence-transcoder.sock`. |
| `REQUESTS_URL`    | URL                            | empty                               | Where the server reaches the requests service, `http://requests:8421` with the compose file as it is. A trailing slash is removed.                                                          |
| `REQUESTS_SECRET` | string, at least 32 characters | empty                               | The shared secret presented on every call to the requests service.                                                                                                                          |

Setting only one of `REQUESTS_URL` and `REQUESTS_SECRET`, or a secret shorter than 32 characters, leaves requesting off, and the log says which is missing: `requesting is left off, since ... is missing or too short; it needs REQUESTS_URL and a REQUESTS_SECRET of at least 32 characters`. Compose forwards both, empty by default.

## Media service

The media service is the `valence-transcoder` binary. In the image it is started by the container entrypoint beside the server, so these variables go in the same `valence` service. It reads them directly, and a value that is not a valid number is ignored in favour of the default.

### Listening and tools

| Variable                    | Type                | Default                 | Description                                                                                                                                                                       |
| :-------------------------- | :------------------ | :---------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `TRANSCODER_URL`            | `unix:` path or URL | none                    | If it has the form `unix:/path`, the media service listens on that socket. A network URL is not used to listen.                                                                   |
| `VALENCE_TRANSCODER_SOCKET` | path                | none                    | A socket path to listen on, taking precedence over `TRANSCODER_URL`. For deployments that split the two halves across machines.                                                   |
| `VALENCE_TRANSCODER_ADDR`   | `host:port`         | none                    | A TCP address to listen on, taking precedence over the socket variables. Use it when the media service runs on another machine, and point `TRANSCODER_URL` at it from the server. |
| `VALENCE_FFMPEG`            | path                | `ffmpeg` on the `PATH`  | The FFmpeg binary. The image sets `/usr/lib/valence-ffmpeg/ffmpeg`, Valence's own build.                                                                                          |
| `VALENCE_FFPROBE`           | path                | `ffprobe` on the `PATH` | The ffprobe binary. The image sets `/usr/lib/valence-ffmpeg/ffprobe`. Set both this and `VALENCE_FFMPEG`, not just one.                                                           |
| `VALENCE_VAAPI_DEVICE`      | device path         | `/dev/dri/renderD128`   | The render node used for VAAPI and QuickSync on Linux. NVENC and VideoToolbox ignore it.                                                                                          |
| `RUST_LOG`                  | tracing filter      | `info`                  | The log level of the media service, in `tracing` filter syntax such as `debug` or `info,cache=debug`.                                                                             |

If the socket cannot be bound, the media service prints `could not bind ...` and tells you to set `TRANSCODER_URL` to `unix:<path>` somewhere writable. Outside a container, `/run` is usually not writable, so use a temporary path such as `unix:/tmp/valence-transcoder.sock`.

### Directories

| Variable                | Type                  | Default                                                  | Description                                                                                                                                                                                               |
| :---------------------- | :-------------------- | :------------------------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `VALENCE_TRANSCODE_DIR` | path                  | the system temporary directory plus `valence-transcodes` | Where live transcode segments are written. Choose the fastest local disk. The image sets `/transcodes`.                                                                                                   |
| `VALENCE_ARTEFACT_DIR`  | path                  | the system temporary directory plus `valence-artefacts`  | Where rendered previews and thumbnail sheets are kept. Map a volume here, or they are lost when the container is recreated. The image sets `/cache/artefacts`, and compose forwards it with that default. |
| `VALENCE_MEDIA_ROOTS`   | colon separated paths | empty                                                    | The directories the media service may read media from. The image sets `/media`.                                                                                                                           |
| `VALENCE_WRITE_ROOTS`   | colon separated paths | empty, which means nowhere                               | The directories it may write finished re-encodes into. The image sets `/media`. Without it every re-encode is refused.                                                                                    |

The media service warns at startup, and the admin page repeats it, if the artefact directory is not on a volume that survives a container being recreated.

## Running from source

When you run the server with `pnpm dev`, `apps/server` and `apps/requests` load the `.env` file at the repository root, and the transcoder wrapper does too. The `.env.example` file lists the variables you are most likely to set, with commentary:

- `NODE_ENV`, `PORT`, `DATABASE_URL`, `MIGRATE_ON_START`, `ANNOUNCE_ON_NETWORK`
- `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `TRUSTED_ORIGINS`, `COOKIE_SECURE`
- `AUTH_RATE_LIMIT_ENABLED`, `AUTH_RATE_LIMIT_WINDOW_SECONDS`, `AUTH_RATE_LIMIT_MAX`
- `CATALOGUE_API_KEY`, `IMAGE_CACHE_DIR`, `TZ`
- `VALENCE_VAAPI_DEVICE`, `VALENCE_FFMPEG`, `VALENCE_FFPROBE`, `TRANSCODER_URL`
- `REQUESTS_URL`, `REQUESTS_SECRET`, `REQUESTS_PORT`, `VPN_URL`, `VPN_API_KEY`, `DEFINITIONS_REPOSITORY`, `DEFINITIONS_BRANCH`, `DEFINITIONS_PATH`
- `MEDIA_ACCESS`, which only compose reads

In development the web client runs on port 5173 and proxies `/api` to 8420, so both origins are needed in `TRUSTED_ORIGINS`. Its example value is `http://localhost:8420,http://localhost:5173`. `pnpm ffmpeg:sync` writes `VALENCE_FFMPEG` and `VALENCE_FFPROBE` into your `.env` without overwriting values you set. Outside a container, set `TRANSCODER_URL` to a writable socket such as `unix:/tmp/valence-transcoder.sock`, since `/run` is root owned.

## Desktop and web

The web client and the desktop client have no configuration of their own. The web client is served by the server, and the desktop client is a window onto a server. During development, `electron-vite` sets `ELECTRON_RENDERER_URL` for the desktop main process to find the dev server, and you do not set it yourself. To sign in from the desktop dev server, add its address to `TRUSTED_ORIGINS`, for example `http://localhost:5174`. The packaged desktop client is trusted without being listed.
