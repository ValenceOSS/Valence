Every release carries the files a deployment needs: `compose.yaml`, `env.example` and the built web client as `valence-web.tar.gz`. The release notes list who did the work, pull request by pull request. The `CHANGELOG.md` at the root of the repository is the full history, written from commit messages.

The OpenAPI document is not attached to releases, on purpose. The running server serves it at `/api/openapi.json`, so the copy you read is always the one that matches your server. This site's [API reference](/api) is generated from the same routes.

## Container images

Valence publishes images to the GitHub Container Registry, named for the repository owner in lower case.

| Image                                    | What it is                                                                                  |
| :--------------------------------------- | :------------------------------------------------------------------------------------------ |
| `ghcr.io/marquescoding/valence`          | The server, web client and media service, as `compose.yaml` names it at the time of writing |
| `ghcr.io/marquescoding/valence-requests` | The optional requests service                                                               |

The release workflow builds both images from the repository and pushes them under the owner name in lower case, so if the compose file in the release you downloaded names a different owner, use that one. Pull what your compose file names, and treat the compose file as the source of truth. The package page for the server is at [github.com/ValenceOSS/Valence/pkgs/container/valence](https://github.com/ValenceOSS/Valence/pkgs/container/valence).

Three kinds of tag exist, and only releases are `latest`.

| Tag                                 | What it is                                                        |
| :---------------------------------- | :---------------------------------------------------------------- |
| `latest`, `1.0.0`, `1.0`, `1`       | A release. Following `latest` changes only when a release is cut. |
| `1.0.1-dev`, `dev`, `sha-3a2e85d`   | The newest `main`, unreleased, rebuilt at every merge.            |
| `3a2e85d-nightly`, `pr-123-nightly` | A build somebody asked for by hand, usually from a pull request.  |

Use a `-dev` or `-nightly` tag to try something before it ships, and expect it to be rough. Release images are built for `linux/amd64`. See [Updating](/install/updating) and [Rolling back](/install/rolling-back).

Other images in the stack come from their own projects.

| Image                               | Project                                                               |
| :---------------------------------- | :-------------------------------------------------------------------- |
| `postgres:18-alpine`                | [PostgreSQL](https://www.postgresql.org)                              |
| `qmcgaw/gluetun`                    | [gluetun](https://github.com/qdm12/gluetun), the VPN client container |
| `ghcr.io/flaresolverr/flaresolverr` | [FlareSolverr](https://github.com/FlareSolverr/FlareSolverr)          |

## Getting the files

Download the compose file straight from the repository:

```bash
curl -O https://raw.githubusercontent.com/ValenceOSS/Valence/main/compose.yaml
```

Or take the files attached to the release you want, which match that release exactly. The `.env.example` in the repository is written for running from source. The variables a compose deployment reads are in [Environment variables](/reference/environment-variables).

## Where to ask for help

1. Search this documentation, starting with [Troubleshooting](/reference/troubleshooting) and the [FAQ](/start/faq).
2. Ask on [Discord](https://discord.gg/uTtcAHMy9N) for quick questions and setup help.
3. Open an [issue](https://github.com/ValenceOSS/Valence/issues) for something that looks like a bug, with your version, what you expected and the relevant log lines.
4. For a security problem, do not post anywhere public: use the [private advisory form](https://github.com/ValenceOSS/Valence/security/advisories/new).
