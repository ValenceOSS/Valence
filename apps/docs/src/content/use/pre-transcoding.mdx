Pre-transcoding keeps copies of each film and episode beside the original, up to six at different sizes, in a format that modest devices play as they are. When somebody presses play, Valence gives their device the best copy it can play untouched, so the server does not have to convert the original on the fly. It suits a server with plenty of disk and little processing power: the work happens once, overnight, instead of every evening while people are watching.

It is built in, and off until you turn it on. Every copy it makes is an ordinary re-encode, kept alongside unless you choose for the tallest to replace the original, so it uses the same media service, the same queue and the same permission, `media.reencode`, as [re-encoding](/use/settings#encoding-and-re-encoding).

## Where it is

Open the admin area, choose **Encoding**, and find the **Pre-transcoding** card at the top. Change what you need and press **Save**. Nothing changes until you save, except **Pause** and **Resume**, which take effect at once.

The card also shows how many copies have been made, how many are still to make, how many were passed over, what it is doing right now, and the copy being made with its progress. **Start the next copy now** starts the next copy straight away, whatever the hour. **Pause** stops the copy being made and makes no more until you press **Resume**.

## Quiet hours

The quiet hours are read on the same clock as the [scheduled jobs](/use/jobs-and-logs#which-clock-a-schedule-keeps): the timezone in the server settings, then `TZ`, then the host's own. They may run past midnight, so 22:00 to 04:00 works as you would expect. A start and an end on the same hour means the whole day.

When the quiet hours end, the copy being made is stopped and its half-written file deleted, so nothing runs into the day. It starts again from the beginning the next night. A copy you asked for with **Start the next copy now** is left to finish.

Pre-transcoding makes one copy at a time, and only when none of its own is under way. A re-encode an administrator asked for always goes first. If somebody starts watching a film while its copy is waiting to be made, the copy waits until another time rather than failing.

## Which files get a copy

Only films and episodes with a picture. Trailers and other extras, music and books are left alone. A file gets a copy only when the copy would be smaller or easier to play:

- its picture is taller than the quality chosen, or it spends more bitrate than that quality allows;
- it spends more than the bitrate ceiling, where you set one;
- or its codec is one fewer devices play, such as HEVC when the copy is H.264, or an old codec such as MPEG-2.

A copy is never larger than its original, and a file that already has a copy of the same quality, codec and container is never copied again. Valence works through the files in a fixed order and remembers where it got to, so a large library is not read from the top each time.

A file whose copy was refused, for example because its folder is read only, is **passed over** until the settings are saved again, so fix the cause and press **Save**. A file whose copy failed twice is passed over until you change the quality, codec or container of the copies.

## Disk, and write access

Every copy takes disk beside its original. A 1080p H.264 copy of a 4K remux is often around a tenth of its size; a copy of a file that is already 1080p is a larger share of it. The **Remaining** figure, times a typical copy, is roughly what it will need. Keep headroom: filling the disk a media server sits on stops streaming and the database with it.

Valence has to be able to write to the folder each film is in. The shipped compose file mounts media read only, which is sensible, and pre-transcoding cannot work under it. See [Storage and volumes](/install/storage-and-volumes#re-encoding-and-write-access) for how to give it write access, and remember `VALENCE_WRITE_ROOTS` must include the library.

## What the copies are called

Each copy sits in the same folder as its original, named after it with what it is:

```
Film (2016)/
  Film (2016).mkv
  Film (2016) - 1080p H264.valence.mp4
  Film (2016) - 720p HEVC 2000kbps.valence.mkv
```

The name is made only from the original and what was asked for, so the same copy always has the same name and is never made twice. A bitrate ceiling, where there is one, is part of the name. If a file Valence did not make already has that name, Valence refuses to write over it.

**Valence never adds a file whose name ends in `.valence.` and an extension to a library**, so a copy never appears as a second film with its own artwork, progress and thumbnails. A copy belongs to its film, and is deleted with it: deleting a film in Valence deletes its copies too, and so does a film that has been missing from the disk for 30 days, once the library forgets it.

## Seeing and removing copies

In **Media**, open a film's or an episode's menu and choose **Saved copies**. Each copy shows what it is, how large it is and its file name. **Remove** deletes the copy and its file. Copies made by pre-transcoding and copies you kept with **Keep alongside** in the re-encode dialog are listed together.

## How playback uses a copy

When somebody presses play, Valence looks at the original and every copy, and picks the largest picture the device can take without the server converting the video. With the quality on **Auto**, playback moves between copies as the connection changes. Where that copy can be played exactly as it is, the file is sent as it is, with no session on the media service at all. Where it needs only repackaging, a session copies it rather than converting it. The original is still what is converted when nothing else will do.

## The job

The **Pre-transcode the libraries** job (`library.preTranscode`) does the deciding. By default it runs every 15 minutes, and after each copy is finished; each run checks the hours, stops what should not be running and queues the next copy. The copies themselves are made by **Process the re-encoding queue**. Both appear on the [Jobs](/use/jobs-and-logs#job-kinds) page like any other job, and the schedule can be changed there.
