A library is a folder on the machine running Valence that holds one kind of media: films, shows, anime, music or books. Valence reads what is in it, looks each thing up, and presents the result on the Home, Films, Shows, Music and Read pages. This page covers adding and managing libraries, how the scanner reads names, how to fix a wrong match, and how visibility and hiding work.

Everything here happens in the admin area, under **Content** then **Libraries**, at `/admin/libraries`. You need the relevant permission for each action, listed in the table near the end of the page.

![The admin Libraries panel listing three libraries with their type badge, path, item count, last read time and an Idle state.](/screenshots/admin-libraries.png)

## Adding a library

1. Open the admin area and choose **Libraries**.
2. Open the menu at the top right of the panel and choose **Add library**.
3. Enter a **Name**. It is only a label for you.
4. Choose a **Type**.
5. Enter the **Path**, or press **Browse** to pick it.
6. Press the confirm button. The library is created but not scanned yet: adding is quick and scanning is not, so they are separate steps.

### Types

| Type   | Reads like | Holds                                                                                           |
| ------ | ---------- | ----------------------------------------------------------------------------------------------- |
| Movies | Films      | One film per file or per folder.                                                                |
| Shows  | Series     | Episodes, grouped into seasons and series.                                                      |
| Anime  | Anime      | Japanese animation, kept apart from other series, with its films beside it. Shown under Shows.  |
| Music  | Music      | Tracks, grouped into artists and albums.                                                        |
| Books  | Books      | Comics and books, one shelf entry per book.                                                     |
| Manga  | Books      | The same as Books, with the badge Manga.                                                        |
| Custom | You choose | A type name of your own, such as Documentaries, that reads like one of the four built in kinds. |

The type decides how files are read. Manga and Custom only change the label. Under the hood every library is one of `movies`, `shows`, `anime`, `music` or `books`.

Anime is a kind of its own, so it can be treated as anime. Its shows are read, matched and shown like Shows, and appear under Shows on every app. Its films sit beside them, each in a folder of its own named with its year (`Film (2022)/Film (2022).mkv`), and appear among your films. Requests for anime are worked out by cour, and its shows are looked up on AniList; see [Anime](/use/requests#anime). Anime libraries don't hand requests to Sonarr. A Shows library added with the Anime type before anime was a kind of its own says so in its settings, where **Holds** turns it into an anime library, or back.

### Choosing the path

The path is a folder on the machine running Valence, not on the device your browser is on. **Browse** opens a folder browser that walks the server's own folders:

- It opens on the folder you have already typed, if it exists, and otherwise on the places worth starting from.
- Only folders are listed, because a library is a folder.
- The trail along the top jumps back to any folder on the way down. The folder you are looking at is the one that is chosen, not one of the folders inside it.
- **Parent folder** goes one level up, and **New folder** creates a folder in the one you are viewing, so you can give a library somewhere to live without leaving the page.
- If Valence is not allowed to read a folder, the browser says so instead of listing it. The message is the server's own, and it says what to change.

A library path that is not a readable directory is refused with "That path is not a readable directory."

<Callout title="Docker paths are container paths">
  In a Docker install, Valence can only see folders that you have mounted into the container. Add
  the mount to your compose file first, then use the container side of it here. See [Storage and
  volumes](/install/storage-and-volumes).
</Callout>

## How files should be named

Valence reads names and folders first, and then, if you have a catalogue key, looks the result up in The Movie Database. The cleaner the names, the better the match. The rules below are what the scanner really does.

### Files it will read

| Library          | Extensions read                                                                                     |
| ---------------- | --------------------------------------------------------------------------------------------------- |
| Movies and Shows | `mkv`, `mp4`, `m4v`, `mov`, `avi`, `webm`, `ts`, `m2ts`, `mpg`, `mpeg`, `wmv`, `flv`, `ogv`, `3gp`  |
| Music            | `mp3`, `flac`, `m4a`, `aac`, `alac`, `ogg`, `oga`, `opus`, `wav`, `aiff`, `aif`, `wma`, `ape`, `wv` |
| Books            | `cbz`, `zip`, `cbr`, `rar`, `pdf`, `epub`                                                           |

Files starting with a dot are ignored. So is the `.valence` folder that Valence keeps beside your media for re-encoded copies, and so is any file whose name ends in `.valence.` and an extension, such as `Film (2016) - 1080p H264.valence.mp4`, which is a copy Valence keeps beside its film (see [Pre-transcoding](/use/pre-transcoding)). A kept copy never appears as a second copy of the film, and is deleted with it.

### Films

A film needs a title and, ideally, a year. Both come from the file name and its folder:

```text
Movies/
  Film (2016)/
    Film (2016).mkv
  Another Film (2019)/
    Another Film (2019).mkv
    Another Film (2019) - B&W.mkv
  Sequel 2 (2025).mkv
```

- The year is taken from a four digit number between 1900 and 2099. A bracketed year such as `(2016)` is preferred over a bare one.
- Everything after the year, and release noise such as `1080p`, `BluRay`, `x265`, `HDR`, `DTS`, `AMZN` and group tags, is dropped. Dots, underscores and brackets become spaces.
- A number that comes before the release noise is part of the title (`Sequel 2`). A number that comes after it is treated as a channel count and dropped.
- If a folder has a name with a year, such as `Film (2016)`, the folder is believed over the file. That makes a collection readable even when the file inside is called `movie.mkv` or `title00.mkv`.

### Several cuts of one film

When a folder is named after a film and every file in it begins with that name, the files are treated as versions of the one film. The file named exactly like the folder is the main one, and the others take their label from what follows the name:

```text
Another Film (2019)/
  Another Film (2019).mkv
  Another Film (2019) - B&W.mkv
  Another Film (2019) - Director's Cut.mkv
```

The film's dialog then offers **Choose version**. Files that merely sit in the same folder without sharing a name are separate films.

### A film kept as several files

A film split across files plays as one film when each file's name ends with a part word, `cd`, `dvd`, `part`, `pt`, `disc` or `disk`, and a number or a letter from a to d:

```text
Film (1999)/
  Film (1999) - cd1.mkv
  Film (1999) - cd2.mkv
```

A part word in the middle of a title, as in `A Saga Part 1 (2010).mkv`, makes no part of anything. A film kept this way never plays its own files directly, though a pre-transcoded copy of it can, its own text subtitles aren't burned in, and re-encoding it can't replace its files.

### Disc rips

A Blu-ray copied whole, with its `BDMV` folder, is read as one film, named after the folder that holds `BDMV`.

### Extras

Trailers, featurettes and similar are recognised in three ways, and all three attach the extra to the film or series it belongs to:

- A folder named for what it holds: `trailers`, `behind the scenes`, `deleted scenes`, `featurettes`, `interviews`, `scenes`, `clips`, `shorts`, `samples`, `extras` or `other`. A folder such as `Season 1 Extras` also counts.
- A suffix on the file name, such as `Film (2016)-trailer.mkv`, provided a file called `Film (2016)` sits beside it. The accepted suffixes are `trailer`, `behindthescenes`, `deleted`, `deletedscene`, `featurette`, `interview`, `scene`, `clip`, `short`, `sample` and `extra`.
- A file called only `Trailer.mkv` (or one of the other words) that sits beside exactly one other video.

A film that happens to be called `The Short` is still a film, because a suffix only counts when there is a matching film beside it.

### Shows

Episodes are recognised from the file name. These patterns are understood:

| Pattern                       | Example                                                                                                                     |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Season and episode            | `Show Name - S02E04 - Episode Title.mkv`                                                                                    |
| A run of episodes in one file | `Show Name S09E19E20.mkv` (filed under the first number)                                                                    |
| By the day it aired           | `Show Name 2017.04.20.mkv` or `Show Name 20-04-2017.mkv`, for a daily programme, matched to the episode that aired that day |
| Number by number              | `Show Name 2x04.mkv`                                                                                                        |
| In words                      | `Show Name Season 2 Episode 4.mkv` (Series works as well as Season)                                                         |

The series name comes from the file name before the numbering, or from the folder above it. A season folder is recognised when it is called `Season 2`, `Series 2`, `S2` and similar, and a `Specials` folder is read as season 0. A recommended layout:

```text
Shows/
  Show (2000)/
    Season 1/
      Show - S01E01 - Pilot.mkv
    Season 2/
      Show - S02E01 - Episode Title.mkv
```

Two further conveniences exist:

- A folder of consecutively numbered files with the same stem (`Show 01.mkv`, `Show 02.mkv`) is read as one season, numbered from the files. The folder needs at least two files with different numbers.
- A file in a Shows library from which no series could be read is treated as a video rather than guessed to be a film, so a badly named episode does not appear among the features.

If a corrected match is stored against a series, a season added later to the same folder inherits it, so it does not appear as a second show.

### Music

Music is read from tags first, not from paths. Artist, album artist, album, disc number and track number come from the file. The folder only stands in for the album name where no tag names one.

- A record with a guest on every track stays one album, because an album belongs to its album artist. An album marked as a compilation belongs to Various Artists.
- Every track is also linked to each artist it credits, so a guest verse appears on the guest's page.
- If a track has no title tag, the file name is used, with a leading track number such as `01 - ` removed.
- Album artwork comes from the front cover inside the first track that has one, and otherwise from a cover image in the album folder. An artist picture comes from an image beside their albums.
- Lyrics come from the tags, or from an `.lrc` or `.txt` file with the same name beside the track. A lyrics file added or changed later is noticed on the next scan.

### Books

- A folder is a series and each file inside is a chapter. A file directly in the library root is a book of its own.
- Titles lose bracketed text and chapter or volume numbering (`ch`, `chapter`, `vol`, `volume`, `c12`, `v3`). Chapter numbers are read from `Chapter 12`, `c012`, `#12`, `Vol 3` or `v3`, and otherwise from the last number in the name that is not a year.
- What a file says about itself wins over its path. A comic's `ComicInfo.xml` provides series, volume title and writer.
- Where a book's files don't name its author, the folder it sits in does: `Author/Title`, or `Author/Series/2 - Title` for a book in a series. A book directly under a series folder, `Series/1 - Title`, gets no author from its path.
- A book's layout is decided by its first chapter: fixed for page images and PDF, reflowing for EPUB. Mixed folders are reported as a problem rather than quietly combined. Page based books open reading right to left by default and reflowing books left to right, and you can change either in the reader.

See [Playing media](/use/playing-media#reading-books) for how books are read.

### Renaming files to the pattern

Files named some other way can be renamed to the pattern above, the one Valence's requests file by and Jellyfin, Plex and Emby read. On the Media page, choose **Rename to the naming pattern…** from a title's menu, a season's or an episode's, or from **More** on the selection bar for every title ticked. The dialog lists each file's name now, struck through, above the name it would get, with how many subtitles and other files beside it go along. Untick any file to leave it as it is.

- A film becomes `Title (Year)/Title (Year).mkv`, keeping what its name said after the year, such as `Title (Year) Bluray-1080p.mkv`, and a version of it `Title (Year) - Extended Cut.mkv`, by the name chosen for it under **Versions of this film**. An episode becomes `Show (Year)/Season 01/Show (Year) - S01E01 - Episode Title.mkv`, and a file of several episodes `S01E01-E02`. A catalogue number in the title's folder name, such as `[tmdbid-603]`, stays on the folder.
- A title's folder that holds nothing else is renamed whole, so its artwork, NFO files and extras go with it, and so is a season's folder. Otherwise each file moves out on its own, and a folder left empty is removed.
- Where another file already has the new name, **When the new name is taken** either leaves the file as it is or adds the next free number, such as ` - 2`.
- Watch history, ratings, edits, version names, episode pins and every other choice made for a file move with it. The files are read again once they have moved.
- Files already named to the pattern are left, as are titles not yet matched to TMDB (match them first, since the name would only be a guess), films kept as several part files, and extras on their own. The dialog says how many of each.

## Scanning

A scan reads the library folder, works out which files are new, changed or gone, and reads only those. A file that has gone is held for 30 days as missing rather than forgotten: it disappears from the library, and comes back as it was, with everybody's progress, if it reappears in that time, as it does when a network share mounts late. After 30 days it is removed. A file whose size and modification time have not changed is skipped, so a library of twenty thousand items that gained two costs two probes.

Open the actions menu next to a library:

| Action                    | What it does                                                                                                                                                               |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Scan for changes          | Reads new, changed and removed files. This is the everyday action.                                                                                                         |
| Upload media              | Sends files from your device into the library.                                                                                                                             |
| Read every file again     | Probes every file rather than only the changed ones. Nothing is deleted, but on a large library it takes a long while and keeps the server busy. It asks for confirmation. |
| Generate missing previews | Films and shows only. Makes hover previews that are missing.                                                                                                               |
| Library settings          | Opens the per library settings described below.                                                                                                                            |
| Delete library            | Forgets the library. It asks for confirmation.                                                                                                                             |

The menu at the top of the panel adds **Scan all libraries** and **Reset and rebuild**, which deletes every item in every library and reads it all again from scratch. Watch progress and marked intros go with it, and it cannot be undone.

The **Last scanned** column reports when the library was last scanned and what changed. While work is running the **State** column shows a badge and an information button that opens a live view of what the library is doing.

### Automatic scans

A scan of every library runs daily at 03:00 by default, as a scheduled job. You can change or add triggers on the jobs page, described in [Jobs and logs](/use/jobs-and-logs). Reading is queued library by library. The slower follow up work (intros, previews, scrub thumbnails) is queued separately, so you can start watching a library as soon as it has been read.

### Leaving files and folders out

Some files should never be in a library: one that is broken and stutters every time it plays, a folder of behind the scenes clips, a copy you keep only as a backup. Leave it out, and every scan from then on passes over it as if it were not on the disk.

Choose **Exclude from library** from the actions menu of a film, an episode or a series on the **Media** page, or of any file or folder in its **Folders** view. Leaving out a series leaves out its folder. You can say why, which is shown beside it later. Leaving out a folder leaves out everything inside it, and matches whole folder names, so leaving out `Extras` does not touch `Extras Archive`.

What Valence found there goes at the next scan, which starts straight away. Nothing is deleted from the disk.

Everything left out of a library is listed at the foot of its **Library settings**, with why. **Restore** forgets it, and the next scan reads it again as a new file.

### Deleting a library

Deleting removes the library and everything Valence knows about its contents: watch progress, ratings, favourites, previews and thumbnails. Playlists that hold items from it keep their places and say what they lost. The files on disk are never touched, and anything running for the library is stopped.

## Per library settings

**Library settings** in the actions menu opens a dialog with these options.

| Setting                         | Default                              | What it does                                                                                                                                                                                                                   |
| ------------------------------- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Holds                           | What it was added as                 | Shows and Anime libraries only: whether it holds series or anime. Turning a library into an anime one stops it handing requests to Sonarr.                                                                                     |
| Metadata language               | TMDB's default, English              | Films, shows and anime only: the language TMDB is asked for titles, overviews and logos in, from the next scan or refresh. A title TMDB hasn't translated stays in English.                                                    |

| Write NFO files                 | Off                                  | Films, shows and anime only: each time a title is edited, Valence writes its NFO beside the file, and a show's tvshow.nfo in its folder, in Kodi's format, which Jellyfin and Emby read too. An NFO already there is replaced. |
| Force default audio track       | Off                                  | Makes previews and playback prefer this language when a file has a track in it. A file with no matching track keeps its own default. Changing it offers to regenerate previews, so the library is not left in two languages.   |

| Accept requests                 | On                                   | Whether media that people request can be filed in this library.                                                                                                                                                                |
| Quality profile for requests    | Whichever profile names this library | Which quality profile releases for this library are judged by.                                                                                                                                                                 |

| Higher-quality requests         | Ask me                               | What happens when somebody asks for a title already requested, at a higher quality profile: ask you on the title's page, switch the request to it, keep the one it has, or, for films, keep both versions.                     |
| Keep new episodes with the show | On                                   | Shows only: new episodes of a show the library has go into the show's own folder rather than the download folder for requests.                                                                                                 |
| Download requests with          | Valence                              | Whether Valence fetches what is asked for, or a connected Radarr, Sonarr or Lidarr. See [Requesting](/install/requesting#handing-a-library-to-an-app).                                                                         |

Below the settings, **Excluded from this library** lists the files and folders its scans pass over, as described in [Leaving files and folders out](#leaving-files-and-folders-out).

The request settings are explained in [Requests](/use/requests). The count of files rendered at once is also bounded by what your hardware proves it can do, so it never exceeds the number of hardware encodes the machine can run. See [Hardware transcoding](/install/hardware-transcoding).

### Locking a library

A library can be locked behind a password or PIN from its settings, under **Lock**, with how many minutes an unlocking lasts (5 minutes to a day, an hour unless you say otherwise). While it is locked its titles are left out of the home rows, search, browsing and everywhere else titles are listed, for everybody, administrators included.

The library itself is still offered, as a box saying it is locked with somewhere to type the password or PIN. Unlocking it shows its titles on that device, for that account, until the lock comes back on its own. The unlocking is kept in a cookie the server signs, so it cannot be made by hand, cannot move to another account, and ends early if the password is changed. Five wrong tries in a minute are refused until the minute is up. **Take the lock away** removes the lock for good.

A lock is a way to keep a household's late-night films out of the way, not a wall: anybody who knows the password or PIN can open it, and it does not change which accounts may reach the library at all, which [account restrictions](/use/accounts-and-roles) decide.

## Uploading media

**Upload media** in the actions menu sends files from the device you are using into a library. Drop files or whole folders onto the dialog, or press to choose them. Files are uploaded one after another, keeping the folder structure they came in, and each shows its own status: waiting, uploading, uploaded or failed with the server's reason.

Only files the library would read are queued, and anything left out is listed, so nothing is uploaded to a place no scan would look. For Movies and Shows the video extensions above are accepted along with subtitles (`srt`, `vtt`, `ass`, `ssa`). Music takes audio files and Books take book files.

Every part of the path must be a plain name. Names starting with a dot, names containing a backslash and paths more than 12 folders deep are refused, and nothing can be written outside the library folder or into the `.valence` folder. When the uploads finish, the library is scanned so the new files appear without a further step.

## Metadata sources

Valence uses these sources, all configured in the admin **Settings** panel and described in full in [Settings](/use/settings):

| Source                             | Used for                                                                                      | Key needed                                                                                        |
| ---------------------------------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| The Movie Database (the catalogue) | Titles, years, overviews, cast, artwork, logos, certificates and trailers for films and shows | A free catalogue key. Without one, titles and years come from filenames alone.                    |
| OMDb                               | Rotten Tomatoes scores                                                                        | An optional free key. Scores fill in as titles are scanned again.                                 |
| TheAudioDB                         | Artist photographs and music videos                                                           | An optional key. Without one, a free key is used that finds only one music video for each artist. |
| Cover Art Archive and LRCLIB       | Album covers and song words                                                                   | None. Enabled by the **Music details** switch in Settings › Online services, off by default.      |

Nothing a file already carries is replaced by fetched music details, and each album, artist and song is asked about once, on the next scan.

<Callout title="Outside requests are opt in">
  Fetching catalogue trailers and music details are the only things Valence does that reach outside
  your server, and both are off until you turn them on. A trailer file beside the film is always
  used in preference.
</Callout>

## The Media page

**Media**, under **Content**, is where a library's titles and its files are managed together. It has two tabs, **Titles** and **Folders**, which share one search field and one library. Choose the library from **Which library** in the search field's menu, where a library with titles to fix says how many.

### Titles

- **The table.** Each film shows its poster, name and year, then its **Quality**, **Video** and **Audio**, how long it runs, its **Size** and how long ago it was **Added**. A series shows how many seasons and episodes are on the disk and folds open to its seasons and episodes; a film held more than once folds open to each version. Where the files of a title differ, a column says **Mixed**.
- **Opening a title.** Pressing a row opens the title's own page. Pressing a season opens the season's page, an episode opens the episode's page, and a version opens the **Files** tab.
- **What needs a look.** A title missing something is marked **Unmatched**, **No poster**, **There twice** or **Couldn’t be read**. The row above the table narrows it to **All titles**, **Unmatched**, **Duplicates**, **Unreadable** or **Edited**, each with how many. A music or book library offers **No cover** instead.
- **Narrowing and sorting.** **Filters** narrows the list by what a title is missing (including episodes TMDB lists that aren't on the disk), its resolution, HDR, video codec, genre, tag, year, rating, when it was added and whether it has subtitles. Each filter shows as a chip above the table that removes it. Pressing a column's heading sorts by it, and the columns button hides the columns you don't want. The address keeps the library, search, order and filters, so a view can be bookmarked.
- **Saved views.** The bookmark button saves the filters, search and order shown under a name, and lists the views saved for the library. They are kept on this device.
- **Doing several at once.** Tick titles, Shift-click to tick a range, or tick the box in the heading and choose **Select all** with its count for every title that matches, not just those shown. Ticking a series' episode ticks just that episode. The selection bar offers **Edit**, **Refresh** and **Add tags**, with **Merge into one film…** (for two or more films that are really one: choose the film they all are, and the others are matched to it as its versions), **Match automatically…** (for unmatched titles: each is searched for on TMDB, matched only where one entry fits at least 90 out of 100 and clearly better than the rest, and the others are listed with **Fix match** beside each. **Review the rest one by one** then steps through those left, each with TMDB's entries best fit first: choosing one matches the title and moves on, **Skip** and **Previous** step past or back, and **Accept the best fit for the rest** or **Skip the rest** settles all that remain at once), **Add to a collection…**, **Lock all fields**, **Unlock all fields**, **Re-encode**, **Rebuild previews**, **Rename to the naming pattern…**, **Move to another library…** and **Delete** under **More**.
- **Editing several titles.** **Edit** opens every field the titles share. A field they differ in says **Mixed**, and only the fields you touch are changed. A list such as genres can be added to, taken from or replaced. **Find and replace** swaps some words for others in one field of every title: in a list, only a whole entry is replaced, and an emptied one is taken out. The dialog says how many fields it changes on how many titles before you apply it. For series you can edit their episodes instead. The change is one step, and **Undo** in the message that follows takes all of it back.
- **The media menu.** The **…** beside the search holds **Genres and tags**, which renames or removes a genre or tag on every title in the library (renaming one to a name already in use merges the two). For genres, **Do the same to titles scanned later** keeps the rename or removal as a rule that every later scan and refresh follows, listed under **Rules every scan follows** and forgotten from there; **Export as a spreadsheet**, which downloads the titles listed, with their filters, as a CSV file, and **Import a spreadsheet…**, which brings an edited export back: each row is found by its TMDB id, or by its title and year, the dialog lists what would change, and nothing changes until you apply it. The import changes a title's name, sort title, release date and genres. Where an edit no longer has a title, for example after its file was renamed and matched again, it also offers how many **edits without a title** there are, to attach each to a title or throw it away.
- **A title's menu** holds **Open**, **Wrong match?**, **Choose artwork…**, **Show in Folders**, **Rebuild previews**, **Find subtitles…**, **Choose the preview frame**, **Re-encode…**, **Saved copies**, **Rename to the naming pattern…**, **Move to another library…**, **Exclude from library** and **Delete file…** or **Delete series…**, as far as each applies and you're allowed.

### Folders

**Folders** shows the chosen library as it sits on the disk. The trail along the top steps back up, and **New folder** and **Upload here** add to the folder you're in. Each file's menu renames, moves, excludes or deletes it, and ticking several puts **Move** and **Delete** on the selection bar. Where a folder holds subtitles, NFO files or pictures whose video is gone, a button says how many and shows only them. On a phone, a chosen file's details show under the list.

Every file says which title it belongs to, which opens that title's page, and has a status: **In the library**, **Unmatched**, **Extra**, **Excluded**, **Sample**, **Skipped**, **Unreadable**, **Not read yet**, **With its video** for subtitles, NFO files and pictures, **Its video is gone** when their video no longer exists, or **Not a video**. Choosing a file shows its details, with the video a subtitle belongs with, and for a video not in the library, why: what the last scan said of it, or that it was excluded, looks like a sample, sits in a folder scans skip, or hasn't been read yet. A programme's folder shows the programme's name.

Opening a title from **Folders** and pressing **Media** at the top of its page brings you back to the same folder. The address keeps the folder (`?mediaView=folders&folder=`), and links to the old Files page open here.

### A title's own page

A title's page shows its poster, name and year, badges for its best quality and rating, with **Unmatched** where it isn't matched, and at the right its library, what it is matched to in the catalogue, when it was added, and how many files it has and how large they are. **Previous** and **Next** at the top step through the list as it is shown, and **K** and **J** do the same. Its buttons are **Fix match**, **Refresh** and **Open in Catalogue** where requesting is set up, with **Lock all fields**, **Unmatch**, **Open folder** and the title's other actions in its menu.

- **Details** holds every field of the title's metadata in one form, in sections: **Title and release** (including the date added), **Story** (including the trailer, as a YouTube link or video ID), **Classification**, **Origin and crew** (original language, countries, creators, directors and writers), **Ratings**, **IDs** and **Note**. An anime series also shows its AniList and MyAnimeList ids once it has them. Each field saves as you type and says where its value came from: **TMDB**, **File name**, **Edited** or **Locked**. An edited field shows what TMDB says beneath it, with **Reset**. Edits are kept through every scan and refresh, and a daily job notes where TMDB has changed a field you edited. Below the form, **Collections** lists the collections the title is in and adds it to another.
- **People** is the title's cast, in the order every app shows it. Each person's role can be changed, they can be moved up or down or taken off, and **Add a person** finds people in TMDB by name, or adds someone by name alone. The cast says where it came from and goes back to TMDB's with **Reset**.
- **Artwork**, once the title is matched, chooses its **Poster**, **Backdrop** and **Logo**. It says which picture is in use and where it came from, and **Go back to the catalogue’s pick** undoes a choice. Pictures beside the title's files on the disk are offered first, then every picture TMDB has, and fanart.tv's too where a fanart.tv key is set in **Settings** under online services, with its language, size and votes, in the catalogue's order or by votes, size or no lettering first. **Upload from this computer** uses a picture of your own. A choice reaches every file of the title and outlives every scan.
- **Seasons**, for a series, starts with **Episode order** where TMDB has more than its own, such as a Blu-ray or broadcast order: choose the one your files are numbered in, and every episode is read again by it, keeping your edits. Below it, it lists each season and its episodes. A season's menu opens the season's page, and pressing an episode opens the episode's page.
- **Files** starts, for a film held as several versions, with **Versions of this film**: what each version is called, such as Extended Cut, and which one **Plays by default**, with **Play this by default** on the others, and **Split off…** for a version that is really a different film, which opens Fix match for that file alone. Both are kept through every scan. A film's Files tab, and an episode's File tab, also hold **Skip markers**: where the player offers to skip the intro, recap, credits or preview, each with when it starts and ends. Detection finds intros and credits on its own. A marker added or moved here is kept through every detection run after, while one saved as detection found it stays detection's to improve, and taking a marker off lets detection find it again. On a film's Files tab, a file's menu also has **Mark as an extra…**: whether the file is one of the film's extras, and of what kind, such as its trailer, or a film of its own, whatever its name or folder says, kept through every scan until **As its name and folder say** is chosen again. Below them, **Files** is the file manager for the title's own folder: every file with its status and, for a video, its quality, video, audio and length, subtitles and pictures beside their video, and the tools to upload, rename, move, exclude or delete, alongside the title's own file actions. A **Re-encodes** card lists any re-encodes asked of its files.
- **History** lists every change to the title's metadata, who made it and what each field went from and to, with **Undo**.

The page's address names the title and where you are on it (`?media=`, `&titleTab=`, `&season=`, `&episode=`).

### A season's or an episode's page

A season and an episode each have a page of their own, laid out as the series' is. A trail at the top leads back up to **Media**, the series and, from an episode, its season, and **Previous** and **Next**, or **K** and **J**, step to the season or episode before and after it.

- An episode's page shows its still, its name and number, such as S01E02, its quality, and at the right the series, when it aired, how long it runs, its size and when it was added. **Change the episode…**, **Find subtitles** and **Re-encode** are its buttons. **Change the episode…** says which episode the file is whatever its name says, or which episodes a file of several holds, and keeps that through every scan until **Go by the file name again**. Its other file actions are in its menu. Its tabs are **Details** (its title, overview, air date, directors, writers and note), **People** (its guest stars, edited as a title's cast is), **Artwork** (its still, from TMDB's), **File** (the file manager narrowed to its video and the subtitles and pictures beside it) and **History**.
- A season's page shows the series' poster, the season's name and year, and how many of its episodes are here, with **Episodes from** where the season is read from another show. **Fix season match** is its button, described under [A season that is another show](#a-season-that-is-another-show). Its tabs are **Details** (its name, overview, air date and note), **Artwork** (its poster, from TMDB's), **Episodes**, where pressing an episode opens its page, and **History**.

A season's page adds `&part=season` to the address, and an episode's names it with `&episode=`.

## Correcting a wrong match

Sometimes the catalogue matches a file to the wrong film or series, usually because the name was ambiguous. Fix it once and the fix sticks across future scans.

1. Open the title's page and press **Fix match**, or choose **Wrong match?** from its menu in the list.
2. Fix match searches under the title's name as soon as it opens, and shows the file or folder it is matching. Change the name, choose **Film** or **Show**, or paste a TMDB address or number, an IMDb id or a TVDB id. Each result says how well it fits, and **Show more** lists the next page.
3. Choose the right entry. Fix match then compares the title with it field by field. Fields that would change are ticked to take the new value, and fields you edited or locked are left as they are unless you tick them.
4. Press **Apply**. Valence records the correction and reads the files again, and every later scan uses it. For an episode the correction applies to every episode of the series.

### A season that is another show

TMDB sometimes lists a season as a show of its own, such as a revival with new presenters, while your files, often named by Sonarr from TVDB, carry on the old show's numbering as its next season. Valence then finds no such season, and its episodes have no stills, titles or air dates from TMDB.

1. Open the season's page and press **Fix season match**. It's there for a series kept in a folder of its own, which is how Valence knows a new file belongs to that season.
2. It searches TMDB under the series' name. Choose the show the season really is; the year beside each tells a revival from the show it carries on.
3. Choose that show's season, and press **Apply**.

The series stays the one it is matched to, so it is not split in two. Only that season's episodes, its poster and its pictures come from the other show, by their episode numbers, new episodes of it are read the same way when they arrive, and what the other show has still to air shows on the release calendar and under Coming up as that season's. **Episodes from** on the season's page says which show and season they come from, and **Use the show's own season** in the same dialog goes back. Changing which show the whole series is matched to doesn't touch it.

**Refresh** on the title's page, in a title's menu in the list, or on the selection bar asks TMDB again: **Update details** keeps the match and every edit, **Update some fields** asks only for the fields you tick, **Match again** forgets the match and finds it again from the file names, **Fetch artwork** fetches the pictures again, and **Read the files again** reads each file's streams and length afresh. **Unmatch** takes the title back to what its file names say and keeps it unmatched. You need the media override permission.

## Previews and artwork

Hover previews are the short clips that play when you rest on a title. They are made from the film at a point a fifth of the way in by default. That guess can land on a title card or a spoiler, so you can choose the moment yourself:

1. In **Media**, open the row's actions and choose **Choose the preview frame**.
2. Drag the two handles along the strip of frames to set where the clip starts and ends.
3. Save. To go back to the automatic moment, choose the automatic option in the same dialog.

A title's poster, backdrop and logo are chosen on its page's **Artwork** tab (see [A title's own page](#a-titles-own-page)), or with **Choose artwork…** in its menu. Other actions in the same menu rebuild a title's previews and thumbnails from the file, and **Re-encode** starts a re-encode (see [Settings](/use/settings#encoding-and-re-encoding)). Preview quality, which sets how sharp and how large the clips are, is a server setting and defaults to High. Changing it remakes every preview in the background.

## Who can see what

Valence has three layers of visibility, and they do different jobs.

### Per account library access and age limits

An administrator can stop an account reaching a library at all, or set an age ceiling per library, from **Accounts** in the admin area. Access is stored as refusals, so every account reaches every library until somebody says otherwise, and a new account needs no extra step before it can watch.

- **Age limit**: choices are No ceiling, Suitable for all, Up to 8, Up to 12, Up to 15 and Up to 18. The ceiling is compared with the certificates the catalogue supplies, read for the country chosen under **Age ratings** in Settings (default GB).
- **Allow unrated**: items nobody has certificated are refused to an account with a ceiling unless this is on. That is deliberate: an unrated title shown to a child because a field was missing is the failure the feature exists to prevent. Music is never treated as unrated.
- **Exceptions**: on a title's dialog, **Who can watch this** lets an administrator allow or deny a single film or series for an account. A deny always wins, an allow beats the ceiling, and otherwise the library ceiling applies.

An administrator sets limits on an account, and they hold for every profile on it. An account's owner can also limit one of its profiles, such as a child's; that limit is a household control, since whoever holds the account can pick another profile unless it has a PIN. Give a child their own account if you want a limit that holds against them. Administrators and share guests are not subject to ceilings. Full detail is in [Accounts and roles](/use/accounts-and-roles).

### Hiding, per profile

Anyone can hide something from their own browsing. **Hide this** in a title's menu (and the same for a series or a whole library) removes it from that profile's rows, searches and the randomiser. Nothing is deleted and a half watched position is kept. Hiding belongs to one profile, not to the account, so it never affects anybody else. Bring things back from **Hidden** in your account area.

Hiding is a preference, not a restriction. It cannot be used to reach something an account is not allowed to see, and nobody can hide what they were never allowed to see in the first place.

### Administrator hiding

The **media.hide** permission lets a role hide an item from every profile, rather than only its holder's own. See [Accounts and roles](/use/accounts-and-roles) for the permission catalogue.

## Permissions used on this page

| Permission       | Allows                                                                                 |
| ---------------- | -------------------------------------------------------------------------------------- |
| `library.create` | Adding libraries and using the folder browser, including creating folders.             |
| `library.edit`   | Changing library settings, uploading media, and leaving files and folders out.         |
| `library.delete` | Deleting a library.                                                                    |
| `jobs.run`       | Scanning, reading files again, generating missing previews and watching scan progress. |
