Requesting lets anybody with an account ask for something the server does not have. An approved request is searched for on your indexers, sent to your download client, filed into the right library and announced to the person who asked. This page covers both sides: asking, and running the queue behind it.

Requesting is an optional part of Valence. It needs the requests service, indexers and a download client. If your install does not have it, none of the request screens appear. To set it up, see [Requesting](/install/requesting).

## Asking for something

Open **Requests** from the main navigation. The page has six tabs.

| Tab         | What it shows                                                                      |
| ----------- | ---------------------------------------------------------------------------------- |
| Discover    | Shelves of what is trending, popular and coming soon, plus studios you can browse. |
| Movies      | The full list of popular films, going on as far as you scroll.                     |
| Shows       | The same for series.                                                               |
| Music       | Artists and albums to ask for.                                                     |
| Books       | Books to ask for.                                                                  |
| My requests | Everything you have asked for, and where each has got to.                          |

Which tab is open is kept in the address, so you can link straight to any of them.

### Making a request

1. Find a title on a shelf, or browse Movies, Shows, Music or Books.
2. Open it. The dialog shows the poster, facts, cast and, for an artist, their albums.
3. Choose **Request**. For an artist the button reads **Request this artist**.
4. For a series you can choose which seasons you want; leaving it alone asks for every season. Specials have their own switch and are fetched only when it's on. **Get new seasons as they come** fetches each season that airs later too, and is on unless you turn it off. For an artist you can choose which kinds of release to watch (albums, EPs, singles, live records and compilations).

A series someone has already asked for lists its seasons with the ones already asked for switched on. Switch on more and choose **Add seasons** to add them to the same request.

A title that is already in your library shows an **In your library** badge and an **Open** button instead. A title someone has already asked for shows where it stands (**Waiting for approval**, **Requested**, **Missing**, **Downloading**, **Importing**, **Declined** or **Failed**), so nobody asks twice.

You need `requests.ask` to request films, series and books, and `requests.askMusic` to request artists and albums. Both are part of the default Member role.

### Searching

Search, on the web, phone and TV, finds only what's in your libraries. Where the catalogues have something by the same name that the server doesn't, the results end with a card saying how many there are, with a button that shows them. On the web it opens Discover's own search, which has its own field at the top of Discover and finds films, shows, artists and books; the phone and TV show the films and shows in place, with a button back to the library's results.

A show in your library that's missing episodes that have already aired has **Request more…** on its page. It opens the show's seasons to ask for, with the ones you have in full locked, and fetches only what's missing.

### Approval

What happens next depends on who asked.

- If you hold `requests.autoApprove`, your request is approved at once and the search starts immediately.
- Otherwise it waits with the status **Waiting for approval** until somebody with `requests.approve` decides.

Choosing a release by hand is a separate ability: only accounts with `requests.manage` can pick a specific release when asking.

### Following and cancelling

**My requests** lists each request with its cover, a badge and a line of detail, plus a progress bar for series and artists showing how much has arrived. When a request is available, choose it to open the film, series, album or book in the library.

You can **Cancel** a request until its files have been filed. A cancelled request is not fetched, and anything it had started downloading is deleted. You can ask for the same thing again whenever you like.

### Books

Books can be requested, but Valence does not search for them. A requested book shows **Waiting to be added**: an administrator adds it to the library by hand, and the request completes once it appears.

### Notifications

When something you asked for lands in the library, you get an in-app notification ("Something you asked for is ready"), and a push notification if you have enabled them. Each person can switch this on or off per transport. See [Notifications and webhooks](/use/notifications-and-webhooks).

## Statuses

A request's badge tells you where it stands. The web, phone and TV apps, the admin area, the release calendar and webhooks all use the same words, and the requests list can be filtered by them.

| Badge                | Meaning                                                                                                                                 |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| Waiting for approval | Nobody has decided yet. Nothing is fetched.                                                                                             |
| Declined             | An administrator declined it, with a reason if they gave one. It can still be approved later.                                           |
| Requested            | Approved, and nothing searched for yet. The requests list says which of the next three it is.                                           |
| Looking it up        | For a series or artist, Valence is working out what there is to fetch.                                                                  |
| Queued to search     | It is out, and will be searched for in a moment.                                                                                        |
| Not out yet          | Held until the release date (or the next episode or album) the catalogue gives.                                                         |
| Missing              | Searched for and not found. It is searched again every few hours.                                                                       |
| Searching            | An indexer search is running.                                                                                                           |
| Downloading          | The download client is fetching it, or is about to. Paused, Stalled or Failed beside the progress says the download client has stopped. |
| Importing            | The download finished and is being placed into the library, or is waiting for the library to find it.                                   |
| In the library       | It is in the library.                                                                                                                   |
| Failed               | Something went wrong, with the reason shown.                                                                                            |
| Waiting to be added  | A book, which is added by hand.                                                                                                         |

## The admin side

Administrators manage requesting under the **Requests** heading of the admin area.

| Panel     | Purpose                                                                       |
| --------- | ----------------------------------------------------------------------------- |
| Overview  | Whether the requests service answers, its version, the VPN and the indexers.  |
| Catalogue | Every title the libraries hold and every title asked for, with where each is. |
| Indexers  | The sites Valence searches for releases.                                      |
| Profiles  | Quality profiles that judge releases.                                         |
| Downloads | The queue of downloads, and the download clients.                             |

### Overview

The Overview panel checks that the requests service is answering, shows which version is running, tells you whether the VPN the downloads travel through is up, and lists how many indexers are switched on and which are failing. **Check now** asks again rather than waiting for the next scheduled check, which happens every five minutes by default (see [Jobs and logs](/use/jobs-and-logs)).

### The Catalogue

The **Catalogue** lists every title the libraries hold and every title asked for, one poster each, with a tab for each kind of library the server has: Films, Shows, Music and Books. A bar along the foot of each poster says where the title stands, filled to how much of it is in the library, and hovering it says so in words.

The tiles above the posters count the titles at each status and filter the grid to one of them:

| Status         | Meaning                                                                  |
| -------------- | ------------------------------------------------------------------------ |
| In the library | Everything it follows is here.                                           |
| Downloading    | Something of it is on its way.                                           |
| Missing        | Something it follows is out but not here, or nothing of it is here yet.  |
| To approve     | Someone asked for it, and it waits for approval.                         |
| Failed         | Something of it failed, with the reason on its page.                     |
| Not followed   | It's in the library, but nobody asked for it, so nothing new is fetched. |

Search by title, narrow a tab to one library where there's more than one of that kind, narrow Music to artists or albums and Books to ebooks or audiobooks, sort by when a title was added or by name, and choose how big the posters are. **Add a title** asks for something from the catalogues; for something no catalogue knows, **Search the indexers instead** searches every indexer by hand and files what you pick into a library. **Search all missing** searches again, now, for everything still missing.

**Select several** puts a box on each title waiting for approval, to approve or decline several at once. A reason given when declining several is shown to everybody who asked for one of them.

Approving and declining need `requests.approve`. Seeing everybody's requests, and how their downloads are going, needs `requests.viewAll` (or approve or manage), which the Member role has. Without one of those, a person sees only their own. Anybody can cancel only their own requests.

### A title's page

Open a poster for the title's own page. It shows the title, where it stands, who asked and when, and what can be done:

- **Approve** and **Decline…**, while it waits for approval. Declining takes an optional note, shown to whoever asked.
- **Search missing** searches now for whatever of it is missing.
- **Interactive search** lists every release the indexers have for it, judged by its quality profile and best first, with refused ones and why. Picking one fetches it at once: anything already downloading for the same episodes is stopped and blocked, so it isn't picked again.
- The **…** menu has **Edit** (quality profile, library and seasons), **Fetch only releases I pick** (or **Search for it automatically**), **Mark as in the library**, for something added by hand, and **Remove…**. Removing stops its downloads, and can also delete the files it added to the library. Your own files are never touched.

**Progress** shows a bar of everything the title waits for, coloured by where each part stands, and one row for each download, season packs and single episodes alike. The cross on a row stops that download, then finds a different release, opens interactive search to pick one yourself, or stops getting what it was for. Deleting what it downloaded so far is a choice.

A show's **Seasons** each have a bar of their episodes, a count of how many are here and a switch to follow it. Open a season for its episodes: when each aired, where it stands, the reason on hover where something went wrong, and its file. An artist's page lists its albums the same way. Following a season of a show nobody asked for, or pressing **Follow** on any title nobody asked for, starts fetching it.

**Details** and **On disk** say its quality profile, library and folder, and the files the library holds of it. **Activity** is everything its request has done, newest first, and **Never again** lists the releases it won't try again. Remove an entry to let one be tried again.

### Refetch media

An indexer that can search by catalogue id is asked by the title's TVDB, IMDb or TMDB id first, so a show that goes by another name there, such as "The Office US", is still found; where that finds nothing it's asked by the title. The same release from more than one indexer is kept once, from the indexer with the better priority. A release no download client can take, such as a usenet one with only a torrent client on, is refused rather than tried on every search.

Anything still wanted is searched for again by itself every few hours, and again shortly after the service starts, which also catches things that came out while it was down. **Search all missing** in the Catalogue runs that search now. The service also reads the newest releases on every indexer about every quarter of an hour, so a release appearing on an indexer can be picked up without waiting for the full search.

If a download fails, or runs into trouble that the **Rules** tab of the **Downloads** panel gives up on, Valence removes it, blocklists that release for that request and looks for the next best at once. If filing fails, it tries a few times before marking the item as **Failed** for you to look at.

### Releases, quality profiles and libraries

A **quality profile** decides which releases are acceptable: which qualities, such as WEB-DL 1080p or Blu-ray 720p, in what order, how big they should be, and when a film counts as released. Profiles are managed on the **Profiles** panel and need `requests.manage`. Each library says whether it **Accept requests**, which profile its requests are judged by (by default, whichever profile names that library) and where requests are filed (by default, the library's own folder). See [Libraries](/use/libraries).

For music requests, the **Settings** panel has an option for what a request for an artist watches by default: which of an artist's records are fetched when the person asking did not say. It defaults to albums.

### Indexers

An indexer is a site Valence can search for releases. The **Indexers** panel shows each with its priority, what it can search and its state.

- Add one from the catalogue of supported sites, or add a Torznab or Newznab indexer directly.
- **Test** checks a kept indexer and reads what it can search again. You can also try an indexer before keeping it.
- **Test search** searches that indexer alone, to see what it answers and how long it takes.
- **Test all**, in the panel's corner, tests every indexer that is on, and every one Valence turned off for failing, then says which did not answer and why. It leaves alone the ones you switched off.
- **Disable** and **Enable** take an indexer out of and back into rotation. **Remove** forgets it and its key.

Searching the indexers by hand, by title, mode (anything, films, series, music, books), season and episode, opens from **Search the indexers instead** in **Add a title**, from **Test search** on an indexer, and from **Try it** on a quality profile, which ranks what's found by that profile. From a result you can send it to a download client, copy the magnet link or save the torrent or NZB file.

### Downloads

The **Downloads** panel has three tabs. **Queue** lists every download Valence has sent, with its state (queued, fetching metadata, downloading, stalled, paused, finishing, done, not filed or failed), speed and time left. Each row can be paused, resumed, filed by hand into a library if automatic filing did not, or removed. **Clients** lists your download clients. Valence works with qBittorrent, Transmission, SABnzbd and NZBGet. For each one you set the address, credentials, the category or label Valence puts on what it sends for each kind of library, a priority (the lowest is sent releases first), and, where the client and Valence see the downloads folder by different names, a path mapping.

**Rules** says when Valence gives up on a download. Each rule can be set to **Never**, which leaves the download alone however long it takes:

- **Missing metadata**: a magnet that never learns what files it holds, usually because nobody is sharing it. An hour by default.
- **Stalled**: it started, but nobody is sending it any more. Six hours by default.
- **Too slow**: at the rate it has averaged, it would still be going after this long. A week by default.
- **Unrecognised files**: a torrent holding nothing Valence could file into a library. On by default.

A torrent holding a program, or one its client says has failed, is always given up on.

Removing a client stops Valence sending to it and following what it sent. What it is already downloading carries on in the client.

### Permissions summary

| Permission             | Lets you                                                                           |
| ---------------------- | ---------------------------------------------------------------------------------- |
| `requests.ask`         | Ask for films, series and books.                                                   |
| `requests.askMusic`    | Ask for artists and albums.                                                        |
| `requests.autoApprove` | Skip approval.                                                                     |
| `requests.viewAll`     | See everybody's requests and how their downloads are going.                        |
| `requests.approve`     | Approve or refuse requests.                                                        |
| `requests.manage`      | Set up indexers, download clients and quality profiles, and pick releases by hand. |

## Events

Request activity is available to [webhooks](/use/notifications-and-webhooks) as well: a request being made, approved, refused, chosen, filed or available, a download starting or failing, an indexer failing or recovering, and the requests service or its VPN going down or coming back.
