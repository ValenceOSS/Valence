The official **AniList and MyAnimeList** plugin shows most of what a plugin can do: connecting accounts, a page and a panel of its own, a schedule, an event, notifications and storage. Its full source is in [ValenceOSS/valence-plugins](https://github.com/ValenceOSS/valence-plugins/tree/main/plugins/anilist). This page walks through how it is put together.

## What it does

- Each person connects their AniList account, their MyAnimeList account, or both, from **Anime tracking** in their account.
- When they press **Import my lists**, it imports their lists: every series they have finished, or watched some of, is marked as watched in Valence up to the same episode, if the series is in the library.
- After that first import, an hourly run carries on any import still under way, and once a day reads their lists again, so progress made elsewhere reaches Valence.
- When they finish an episode in Valence, it tells AniList and MyAnimeList, unless they turned **Update my lists when I finish an episode** off.
- A panel on each anime series shows where the person is on their lists.

It asks for four hosts and nothing wider, reads the library but never changes it, and needs `viewing: write` because marking episodes watched is the point.

MyAnimeList accepts only the `plain` PKCE method, so its provider says so with `"pkce": "plain"`, and that needs plugin API 1.3: the plugin asks for `^1.3` and installs on Valence 1.7.0 and later.

## Reading the list

AniList has one GraphQL endpoint. The plugin asks for the person's list with their access token:

```ts
const LIST = `query ($userId: Int) {
  MediaListCollection(userId: $userId, type: ANIME) {
    lists { entries { progress status media { id idMal seasonYear episodes title { romaji english } } } }
  }
}`;

const readAniList = async (valence: ValenceHost, token: string, userId: number) => {
  const response = await valence.http.fetch('https://graphql.anilist.co', {
    method: 'POST',
    headers: { Authorization: `Bearer ${token}`, 'Content-Type': 'application/json' },
    body: JSON.stringify({ query: LIST, variables: { userId } }),
  });

  if (response.status !== 200) {
    throw new Error(`AniList answered ${response.status.toString()}`);
  }

  return AniListCollectionSchema.parse(JSON.parse(response.text));
};
```

What comes back from another service is untrusted, so it goes through a schema before anything uses it. The plugin bundles Zod for that. Entries from AniList and from MyAnimeList are then turned into one shape, an `AnimeEntry` with its titles, year, progress and whichever ids the list gave, and a show on both lists becomes one entry.

## Finding the series in the library

Valence may already know a series' AniList or MyAnimeList id, once its **Find anime on AniList** job has run. If not, the plugin searches by title, and takes a series only when exactly one has that title, once both are normalised, in a year no more than one out. A near miss is never mistaken for the show.

```ts
const findSeries = async (valence: ValenceHost, entry: AnimeEntry): Promise<MediaRef | null> => {
  const byId = [
    ...(entry.anilistId === null
      ? []
      : await valence.library.findByExternalId('anilist', entry.anilistId)),
    ...(entry.malId === null ? [] : await valence.library.findByExternalId('mal', entry.malId)),
  ].find((media) => media.kind === 'series');

  if (byId !== undefined) {
    return byId;
  }

  const wanted = new Set(entry.titles.map(normaliseTitle));

  for (const title of entry.titles.slice(0, 3)) {
    const matches = (await valence.library.search(title, ['series'])).filter(
      (media) =>
        wanted.has(normaliseTitle(media.title)) &&
        (entry.year === null || media.year === null || Math.abs(media.year - entry.year) <= 1),
    );

    if (matches.length === 1) {
      return matches[0] ?? null;
    }
  }

  return null;
};
```

Anything it can't match is listed on the page, so people can see what was left out.

## Marking what was watched

```ts
const importEntry = async (valence: ValenceHost, profileId: string, entry: AnimeEntry) => {
  const series = await findSeries(valence, entry);

  if (series === null) {
    return 'unmatched';
  }

  const episodes = (await valence.library.episodes(series.id))
    .filter((episode) => (episode.seasonNumber ?? 1) > 0 && episode.episodeNumber !== null)
    .toSorted(
      (a, b) =>
        (a.seasonNumber ?? 1) - (b.seasonNumber ?? 1) ||
        (a.episodeNumber ?? 0) - (b.episodeNumber ?? 0),
    );

  for (const episode of episodes.slice(0, entry.progress)) {
    await valence.viewing.markWatched(profileId, episode.id);
  }

  return 'imported';
};
```

Specials, season 0, are left out, because anime lists count them as shows of their own.

A long list takes longer than one call into a plugin may run, so the real import works through a few series at a time: it keeps its place in `valence.storage`, and the page's **Carry on importing** and the hourly run carry it on.

## Keeping it in step

The hourly schedule goes through everyone the plugin acts for. For each person who has imported before, it carries on an import under way, and starts a fresh one once a day. Someone who connected but never pressed **Import my lists** is left alone.

```ts
schedules: {
  sync: async ({ valence }) => {
    for (const profile of await valence.profiles.list()) {
      await syncProfile(valence, profile.id);
    }
  },
},
```

And when someone finishes an episode, the event sends their progress back, unless they turned that off on the page:

```ts
events: async (event, { valence }) => {
  if (event.topic !== 'playback.finished' || event.profileId === null || event.mediaId === null) {
    return;
  }

  if ((await readPreferences(valence, event.profileId)).twoWay) {
    await sendProgress(valence, event.profileId, event.mediaId);
  }
},
```

`readPreferences` reads `preferences:<profile>` from storage, through a schema, and gives `{ twoWay: true }` for someone who never saved a choice.

## The page

The page shows each list and its connect button, a switch for sending progress back with **Save**, and the import: **Import my lists** to start one, its progress and **Carry on importing** while it runs, and once it's done how many shows matched and which weren't found. The connect buttons use Valence's own [connect action](/plugins/accounts-and-oauth#3-offer-a-connect-button).

```ts
act: async (context, request) => {
  const { valence, viewer } = context;

  if (request.action.id === 'save') {
    await valence.storage.set(`preferences:${viewer.profileId}`, {
      twoWay: request.fields['twoWay'] === true,
    });
  } else if (request.action.id === 'import') {
    await startImport(valence, viewer.profileId);
    await continueImport(valence, viewer.profileId);
  } else if (request.action.id === 'continue') {
    await continueImport(valence, viewer.profileId);
  }

  return renderTracking(context);
},
```

`act` returns the page as it now stands, so the person sees the import move on straight away.
