This page takes you from nothing to a plugin running on your own server. It uses the template repository, which has the build, the tests and the packing already set up.

<Callout title="Before you start" tone="quiet">
  You need Node 24 or later, pnpm, and a Valence server where you are an administrator. Read [how
  plugins are kept safe](/develop/plugins) first if you have not: it explains why a plugin can only
  describe its pages rather than draw them.
</Callout>

## 1. Make a copy of the template

Open [ValenceOSS/valence-plugin-template](https://github.com/ValenceOSS/valence-plugin-template) and choose **Use this template**. Then clone your copy and install.

```bash
git clone https://github.com/you/my-valence-plugin
cd my-valence-plugin
pnpm install
```

The template holds:

| Path                              | What it is                                                                    |
| --------------------------------- | ----------------------------------------------------------------------------- |
| `manifest.json`                   | What your plugin is and what it asks for                                      |
| `src/plugin.ts`                   | Your plugin, naming its handlers                                              |
| `src/renderHello.ts` and the rest | The handlers, one to a file                                                   |
| `src/*.test.ts`                   | Tests that call your handlers directly                                        |
| `src/testing/fakeValence.ts`      | A stand-in `valence` for tests                                                |
| `tsconfig.json`                   | Maps `@ValenceSDK/*` to the SDK so your editor and the build find it          |
| `build.ts`                        | Bundles `src/plugin.ts` into one file, `dist/plugin.js`, and packs the plugin |

Pictures your plugin shows, such as its icon, go in an `assets/` folder you add.

The SDK is `@valence/plugin-sdk`, installed straight from the Valence repository and pinned to one commit, with `pnpm-lock.yaml` holding everything else to exact versions:

```json
{
  "dependencies": {
    "@valence/plugin-sdk": "git+https://github.com/ValenceOSS/Valence.git#ef025efe20efca24f7cd52d2d6416fb4df13e1fe&path:/packages/plugin-sdk"
  }
}
```

To move to a newer SDK, put a newer commit of the Valence repository in its place, in `package.json` and in the two `@valence/plugin-sdk` entries of `pnpm-lock.yaml`, keeping `path: /packages/plugin-sdk` in the entry's `resolution`, then run `pnpm install --frozen-lockfile`. When pnpm resolves a git dependency itself it leaves that `path` out, and then installs the whole repository in the SDK's place. The SDK at a commit offers that commit's [plugin API](/plugins/manifest#api-versions), so a plugin that uses something new in it asks for that API in its manifest.

It is published as TypeScript source, so the template's `tsconfig.json` points `@ValenceSDK/*` at it:

```json
{
  "compilerOptions": {
    "paths": { "@ValenceSDK/*": ["./node_modules/@valence/plugin-sdk/src/*"] }
  }
}
```

## 2. Describe your plugin

Edit `manifest.json`. This one adds a page to each person's account that greets them.

```json
{
  "manifestVersion": 2,
  "id": "hello-valence",
  "name": "Hello Valence",
  "version": "0.1.0",
  "apiVersion": "^1.0",
  "author": { "name": "You" },
  "description": "Says hello, and counts how often you have visited.",
  "permissions": [{ "kind": "storage", "quotaBytes": 100000 }],
  "contributes": {
    "pages": [{ "id": "hello", "title": "Hello", "placement": "account", "icon": "star" }]
  },
  "entry": "dist/plugin.js"
}
```

Every field is explained on the [manifest page](/plugins/manifest).

## 3. Write it

`src/plugin.ts` calls `definePlugin` once with your handlers. A page handler's `render` returns a surface: a title and a list of [building blocks](/plugins/building-blocks).

```ts
import { definePlugin } from '@ValenceSDK/host/definePlugin';

definePlugin({
  pages: {
    hello: {
      render: async ({ valence, viewer }) => {
        const key = `visits:${viewer.profileId}`;
        const seen = await valence.storage.get(key);
        const visits = typeof seen === 'number' ? seen + 1 : 1;

        await valence.storage.set(key, visits);

        return {
          title: 'Hello',
          blocks: [
            { type: 'heading', text: 'Hello from your first plugin' },
            { type: 'text', text: `You have opened this page ${visits.toString()} times.` },
            { type: 'button', label: 'Start again', action: { id: 'reset' }, tone: 'secondary' },
          ],
        };
      },
      act: async ({ valence, viewer }, request) => {
        if (request.action.id === 'reset') {
          await valence.storage.delete(`visits:${viewer.profileId}`);
        }
      },
    },
  },
});
```

When `act` returns nothing, Valence calls `render` again and shows the result, which is almost always what you want.

## 4. Test it

Handlers are plain functions, so a test calls them with a stand-in `valence`. The template's `fakeValence()` keeps storage and secrets in memory, answers web requests as the test says, and makes every method a Vitest mock.

```bash
pnpm test
```

## 5. Build and pack it

```bash
pnpm build
```

This bundles your code, checks the manifest and the code against the package rules and writes `packages/hello-valence-0.1.0.vplugin`. See [packaging](/plugins/packaging).

## 6. Install it

In Valence, open **Admin**, then **Plugins**, then **Install from a file**, and choose your `.vplugin` file. Because it isn't signed by Valence or by a key your server trusts, you will see a warning. Read the permissions it asks for, confirm that you trust it, and install. Then open your account: **Hello** is there.
