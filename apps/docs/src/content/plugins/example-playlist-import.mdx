The official **Playlist import** plugin brings playlists across from Spotify and Apple Music, builds them in Valence from the songs you already have, and can ask for the rest. It shows how a plugin uses requests and playlists, and how two very different services can sit behind one page. The full source is in [ValenceOSS/valence-plugins](https://github.com/ValenceOSS/valence-plugins/tree/main/plugins/music-import).

## What it does

- **Spotify:** connect your account, and the playlists you made or collaborate on are listed. You can paste the link of one too; it is read through your account.
- **Apple Music:** paste the link of a public playlist.
- Choose one, and a Valence playlist with the same name is made, in the same order. A song the library has is added; one it doesn't is added as a missing song in its place, which Valence fills in once it arrives.
- If you leave asking for missing songs on, which it is by default, the album of each missing song is requested for you, matched exactly, and follows your usual approval like any request you make yourself.
- A long playlist is worked through 25 songs at a time, and you get a notification when it's done. Up to about 2,000 songs are read, and you're told if there were more.
- One import runs at a time. **Stop importing** on the page ends one early, and so does deleting its Valence playlist.

## One shape for both services

Each source is read into the same plain list of songs, so everything after that is shared.

```ts
type Song = { title: string; artist: string; album: string | null; isrc: string | null };

const readSpotify = async (
  valence: ValenceHost,
  token: string,
  playlistId: string,
): Promise<Song[]> => {
  const songs: Song[] = [];
  let next: string | null =
    `https://api.spotify.com/v1/playlists/${encodeURIComponent(playlistId)}/items?additional_types=track,episode&limit=50`;

  while (next !== null) {
    const response = await valence.http.fetch(next, {
      headers: { Authorization: `Bearer ${token}` },
    });
    const page = SpotifyItemsSchema.parse(JSON.parse(response.text));

    for (const { item } of page.items) {
      if (item !== null && item.type === 'track') {
        songs.push({
          title: item.name,
          artist: item.artists[0]?.name ?? '',
          album: item.album?.name ?? null,
          isrc: item.external_ids?.isrc ?? null,
        });
      }
    }

    next = page.next;
  }

  return songs;
};
```

Spotify's 2026 API calls a playlist's songs its `items`, each one an `item`, and shares them only with the people who made or collaborate on the playlist, so the plugin reads Spotify with the person's own account. It leaves podcast episodes out. The real plugin first asks for the playlist itself, with a `fields` filter, which gives its name and first page in one call and tells it when Spotify won't share the songs, then follows `next` as here, stopping at 40 pages.

`page.next` is an address Spotify gives, but the plugin can only follow it because it is on `api.spotify.com`, a host it listed. If Spotify ever pointed elsewhere, the request would be refused.

The Apple Music reader takes a link such as `https://music.apple.com/gb/playlist/road-trip/pl.u-abc123`, reads the storefront and id from it, and asks `https://api.music.apple.com/v1/catalog/gb/playlists/pl.u-abc123?include=tracks` with the developer token.

## Working in pieces

Every call into a plugin has 30 seconds, and a playlist of a few hundred songs takes longer than that to match. So choosing a playlist only reads it and keeps it in `valence.storage` as an import to do, with the playlist made and a place marker at the start. Each step then takes the next 25 songs:

```ts
const continueImport = async (valence: ValenceHost, profileId: string) => {
  const job = await readImportJob(valence, profileId);

  if (job === null || job.finishedAt !== null) {
    return;
  }

  const adding: (string | MissingSong)[] = [];

  for (const song of job.songs.slice(job.done, job.done + 25)) {
    const track = await valence.music.findTrack({
      title: song.title,
      artist: song.artist,
      ...(song.album === null ? {} : { album: song.album }),
    });

    adding.push(track?.id ?? { title: song.title, artist: song.artist, album: song.album });
  }

  await valence.playlists.add(profileId, job.playlistId, adding);
  await saveImportJob(valence, profileId, { ...job, done: job.done + adding.length });
};
```

Choosing a playlist runs the first step at once. After that, **Carry on importing** on the page runs another, and the plugin's schedule, every 15 minutes, carries on any import that was left. `playlists.add` takes a media id for a song the library has and a missing song for one it hasn't, so the playlist keeps the original order either way.

## Asking for what is missing

Requests are for albums. Once the songs are in, the import notes the playlist, and the plugin's schedule asks Valence which albums its missing songs are on, the same exact-album search the playlist's **Request missing songs** button runs, and asks for each it has found:

```ts
const askForAlbums = async (valence: ValenceHost, profileId: string, playlistId: string) => {
  const missing = await valence.requests.missingAlbums(profileId, playlistId);

  if (missing === null) {
    return true;
  }

  for (const album of missing.albums.filter((each) => !each.isInLibrary && !each.isRequested)) {
    await valence.requests.create(profileId, { catalogueId: album.catalogueId, kind: album.kind });
  }

  return !missing.isMatching;
};
```

`missingAlbums` waits up to 15 seconds. While it says it is still matching, which it also does when MusicBrainz couldn't be reached for some of the songs, the albums found so far are asked for, and the playlist stays noted, so the next run asks for the rest; nothing already asked for is asked for twice. It answers nothing only when the playlist, or the profile it was noted for, is gone, and then there is nothing left to ask for. The person is told how many albums were requested. `requests.create` acts as the person, so if their account can't ask for music, the answer is `refused` and nothing is asked for. The plugin can't get round a person's own request rights. `requests.create` fails, rather than answering, when the requests service didn't answer just now. `askForAlbums` then fails too, without saying the playlist is done, so it stays noted and the next run asks again.

## Saying it is done

A big playlist takes a while, so the page answers straight away and the plugin sends a notification when the last step finishes:

```ts
await valence.notifications.send(profileId, {
  title: `${job.name} imported`,
  body: `${job.found.toString()} of ${job.total.toString()} songs are in your library.`,
});
```

The notification is for the person who imported the playlist, not everyone on their account.
